What I learned

Six things the project taught me that a tutorial wouldn’t.

Don’t invent data to make it tidy. A missing city became “Unknown” and a Customer ID with two names was flagged. Nothing downstream rests on a guess.

Let results redirect the question. A 5.5% repeat rate ended my plan for retention analysis and led to a better one.

Check caveats before reporting a number. A –93.4% monthly “drop” was only a partial month.

Significance is not importance. The p-value says it isn’t chance. The effect size and interval say whether it’s big enough to act on.

Make it reproducible. When my working environment reset, I rebuilt the whole pipeline from the raw file and matched the earlier figures exactly.

Lead with the answer. Stakeholders need the “so what” first and the method second.

What this analysis can’t tell you

Stated plainly, because a finding is only as good as its caveats.

  • One year of data. Some “one-time” customers may simply not have reordered yet. The recommendation includes re-running the segmentation each quarter.
  • The test is partly circular. The segment is defined partly by total spend, so a higher order value is somewhat expected. I therefore also tested two variables not used to build it. Both differ significantly: quantity (7.0 against 4.3 units) and unit price (₹33,892 against ₹19,223), each with p < 0.0001.
  • Association, not cause. The data shows where revenue sits, not why these customers don’t return. The win-back campaign should run as a test with a control group.
